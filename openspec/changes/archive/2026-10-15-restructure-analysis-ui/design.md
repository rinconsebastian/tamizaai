# Design

## Context

See proposal.md for the motivation. The pieces this change works on:

- **Project page and tabs.** `pages/projects/project-page.ts` loads the project into `ProjectContext` and renders a header (back link, name, role badge, form name) and `tmz-tabs-nav` with ten `TabItem`s (the Webhook item only for admins). `shared/ui/tabs-nav.ts` renders Flowbite underline tabs from `md` and one native `<select>` below, with `isActive()` using `paths: 'subset'`. The routes are flat children of `projects/:id` in `app.routes.ts`, each lazy; `''` redirects to `performance`; the Scripts route carries an inline `canDeactivate` guard. `app.config.ts` provides the router with `withComponentInputBinding()` only, so fragments do not scroll.
- **Cross-section links.** Relative `routerLink="['..', section]`: clean-data → scripts (empty state, "See the runs"), indicators → scripts (empty state) plus an absolute link in `indicators/widget-view.ts`, data → overview (retry hint), overview → data, performance, sampling-frame, performance → overview (time zone, completion how-to, enumerator question with `fragment="enumeratorField"`) and → sampling-frame. `create-project.ts` lands a new project on `/webhook`. Five English strings name "the Overview" as a place.
- **Shared components.** `Card` (border, shadow, padding, optional heading), `Alert` (role="alert" only for the danger tone), `Badge`, `Button` (variants primary, secondary, danger, ghost; sizes sm, md; `min-h-10`), `DropdownMenu` (kebab trigger, CDK menu, `danger` items), `FormField` (label, hint, error with `aria-describedby`), `Input`, `Skeleton`, `Table` helpers, `ConfirmDialog`, `ToastService`. Lists use a house pattern: stacked cards below `md`, a table from `md`. Dialogs are CDK dialogs opened with `ariaLabelledBy`, `autoFocus: 'first-tabbable'`, `restoreFocus`; their tests query the overlay container (`project-reference.spec.ts`).
- **Tests.** Vitest specs per section, driven through `testing/project-harness.ts` (`openProjectSection(section, role)`, `byTestId`); `project-page.spec.ts` asserts the tab list per role by reading `nav a`; the dashboard specs read the first three `nav a` to assert their tab position.
- **Research behind this design.** Ten per-section UX audits, each checked by an adversarial reviewer against the code and the specs, and three independent navigation designs scored by two judges. Findings that a reviewer refuted (cosmetic, speculative, or in conflict with a spec scenario) are left out; findings a reviewer corrected are taken in their corrected form.

## Goals / Non-Goals

**Goals:**
- Zero route changes and zero redirects: every existing address, deep link and test harness call keeps working; the grouping is a change in the tab model, not in the route tree.
- Nothing a role can read or do today becomes unreachable for that role; every spec scenario that names a section still holds.
- One set of presentation rules (chrome, disclosures, date format, busy state) applied the same way in every section, so the twelve pages read as one product.
- Keep `data-testid`s stable wherever the element survives, so most existing specs change selectors or expectations, not structure.

**Non-Goals:**
- A separate settings layout with its own route tree, redirects and side navigation (considered and rejected, see D1).
- A cross-section setup checklist or status hub (needs an aggregate endpoint; later).
- Merging General, Webhook and form versions into one "Kobo connection" page.
- New backend endpoints, data model or script-contract changes.
- Sortable column headers replacing the sort selects on Performance, a shared pagination component, or renaming the reused `frame.*` i18n keys.

## Decisions

### D1. Grouped tab model over an empty-path settings layout, no URL change

Two small pieces, no route moves:

- **Tab model.** `TabItem` gains `children?: TabItem[]`. `ProjectPage.tabs()` returns Performance, Clean data, Indicators and a Settings item (label `project.tabs.settings`, gear SVG `aria-hidden`, link to `/projects/:id/overview`) whose children are the seven configuration items. `TabsNav` renders, from `md`, the group as a tab pushed to the row's end with `ms-auto`, styled current and carrying `aria-current="true"` when `isActive()` is true for any child (`routerLinkActive` on the group link alone would only light up on `/overview`; `isActive()` already uses `paths: 'subset'`); the three dashboards keep `routerLinkActive` + `ariaCurrentWhenActive="page"`. Below `md`, the existing single `<select>` lists the three dashboards as options and the children inside `<optgroup [label]="group.label">`; `(change)` keeps navigating through `go()`. No second control on a 360 px screen.
- **Settings layout.** In `app.routes.ts` the seven configuration children are wrapped in one empty-path route `{ path: '', loadComponent: ProjectSettingsLayout, children: [overview, data, scripts (its `canDeactivate` kept), reference, members, sampling-frame, webhook] }` placed after the three dashboard routes. An empty-path route consumes no URL segment, so every address stays exactly as it is, `ProjectContext` (provided by `ProjectPage`) still reaches the pages through the element injector, and the relative `['..', x]` links keep resolving (Angular rewrites the link owner's own last segment, it does not walk route nesting). `ProjectSettingsLayout` renders `<nav aria-label="Settings">` as a Flowbite pill row (`flex flex-wrap gap-2`; links `min-h-10 px-4 py-2 rounded-base text-sm font-medium`, current `bg-brand-softer text-fg-brand` with `routerLinkActive` + `ariaCurrentWhenActive="page"`, others `text-body hover:bg-neutral-secondary-medium`, the usual focus ring), hidden below `md`, then `<router-outlet>`. A row, not a sidebar, so the Scripts `lg:grid-cols-4` editor and the sampling-frame grid keep their width. The row is absent on dashboards by construction.
- A shared `projectSections(id, isAdmin)` helper builds the same list (label key, link) for `ProjectPage.tabs()` and the layout, in the order General, Submissions, Scripts, Reference data, Sampling frame, Members and, for admins, Webhook.
- Focus: after an in-app navigation between children (`Router.navigated` true), the layout moves focus to the newly current pill; on first load nothing is focused.

*Why over a `/settings` route tree with a side navigation (design 2) or purpose-named merged pages with a setup hub (design 3):* both judges scored this model highest on compatibility (no redirects, no retargeted links, no `openProjectSection` churn: the harness interpolates the section string) and consistency (one existing component extended, one small layout); design 2 moves Scripts two clicks away and squeezes its `lg:grid-cols-4` editor beside a sidebar at 1024 px; design 3 deletes two components, splits a 231-line spec and adds a hub that fans out to six endpoints. The user's words are honoured: the row shows the three dashboards and one configuration entry set apart. If a daily-visible Scripts entry turns out to matter for analysts, it is a one-line, role-conditional addition to `tabs()`.

*Why a layout component rather than a second row inside `TabsNav`:* the layout is the natural home for the pill row, the focus rule and any section-level guard, keeps `TabsNav` generic, and uses `routerLinkActive` for the pills instead of hand-rolled active logic.

*Alias:* no `settings` route alias; a memorable URL is not worth a second address for the same page. If `/projects/:id/settings/<slug>` addresses are ever wanted, the same layout takes `path: 'settings'` plus seven one-line relative redirects (Angular rebuilds the final URL with the original query params and fragment), at the cost of eleven link edits, the href assertions and the docs.

### D2. Section names and order inside Settings

General (`overview`), Submissions (`data`), Scripts, Reference data, Sampling frame, Members, Webhook. Route segments are untouched. "Overview" is renamed because the page holds identifiers, diagnostics and admin settings, not a summary; "Data" is renamed because, next to "Clean data", it says nothing, and "Submissions" is what the page counts and synchronizes (the card heading already says so). "Synchronization" was rejected because the page also holds the form versions. The ingestion spec's one scenario that names the section gets a one-word delta; the five strings that name "the Overview" are reworded to actions (D3). Docs follow (task group 13).

*Trade-off accepted:* keeping the old labels would avoid the docs edits and the ingestion delta (the engineering judge's preference), but the five "in the Overview" strings are reworded anyway for D3, the docs are touched anyway for the Settings grouping, and a settings row whose first two entries read "Overview" and "Data" would carry the confusion the audits documented into the new structure.

### D3. Deep links that land

- `app.config.ts`: `withInMemoryScrolling({ anchorScrolling: 'enabled' })`. Angular scrolls to a fragment only if the target exists at navigation end, so targets that render after data loads are handled by the page (next point).
- Ids: `id="runs"` on the runs heading in `pipeline-runs.ts`; `id="form-versions"` on the versions block in Submissions; `id="enumeratorField"` on the enumerator summary row in General, rendered from `project.enumeratorField` (always present) so it exists before the form fields load and survives the field reload after a re-check.
- Fragment handling in General: when `ActivatedRoute.fragment` is `enumeratorField`, expand the enumerator editor and, in an effect that fires when `questionFields()` becomes non-empty, focus the select and `scrollIntoView({ block: 'center' })`.
- Link changes: clean-data "See the runs" → `['..', 'scripts']` with `fragment="runs"`, shown to analysts and admins only (the run id stays visible as text for everyone, matching the empty state's role split); overview "See the form versions" → `['..', 'data']` with `fragment="form-versions"`; the data retry hint loses its link to General because Submissions gains an inline Re-check (D11); the tokenUnreadable alert in General links to Webhook and the Webhook page's status line links to Submissions.
- Copy: `performance.daysUtcAction` → "Set the project time zone.", `performance.seeOverview` → "Re-check the form in Settings", `performance.enumerators.adminLink` → "Select the enumerator question", `performance.completion.howTo` → "…then re-check it in General.", `data.versions.retryLink` removed with the link, `overview.hints.selectEnumeratorField` loses "below".

### D4. Chrome rule

A `tmz-card` frames only (a) a group of controls that belong together (a form, an action row with its status) and (b) headline figures. Lists, tables, logs and the dashboard toolbars are plain sections with an `h2` or a flex row. Stat tiles are label + value with a divider, never a bordered box inside a card. Alerts are used for states that need attention, not for help text. The rule is applied in every section touched (Performance toolbar and tiles, Clean data toolbar, Indicators toolbar and list, Submissions log and versions, Scripts cards, Members list, Webhook second card). The house pattern "cards below `md`, table from `md`" stays for lists that are tables (reference tables, synchronization log, runs); Members becomes one list at every width because it is a people list of a few rows, not a data table.

### D5. Disclosures

`shared/ui/disclosure.ts`: `tmz-disclosure` on native `<details>`/`<summary>` (keyboard toggled, expanded state exposed), with a heading in the summary (wrapped in an `h3` so heading navigation lists it), an optional status text or badge, an `open` input and a `toggled` output, the native marker hidden and a chevron drawn with `aria-hidden`. Used for: "When scripts run" (Submissions), "Set it up in Kobo" steps (Webhook), the indicator inventory (Indicators), the Questions list of the script inputs panel, "Filters (n)" in the widget dialog, the renamed-columns list (Reference data), the sample download's table list is **not** collapsed (the local-dev-kit spec requires it visible). Default-open rules that depend on data ("steps open while no delivery has arrived", "inventory expanded while nothing has published") are evaluated once when the data first arrives, never on a polling refresh, so a group never snaps shut while someone reads it. Each disclosure keeps a stable `data-testid` on the `<details>`; tests that need content inside open it first.

### D6. Set-once settings: value first, edit on request

For settings changed once per project the page shows the current value as text and reveals the existing controls only on request:

- **Synchronization schedule + run settings** (Submissions): one line "Synchronizes every 12 h · checks deletions every 24 h · runs after each synchronization · runs every 24 h · next run …" under the status block; admins get an "Edit" button (`aria-expanded`, `aria-controls`) that reveals the existing schedule form **and** the pipeline settings form (`PipelineSettingsCard` moves here from Scripts, keeping its service calls and field errors), with one Save per form or a merged form; non-admins see the line only. The Scripts page keeps a read-only one-line summary with "Edit" linking to Submissions for admins.
- **Enumerator question** (General): a summary row (`id="enumeratorField"`) derived from `project.enumeratorField` and `questionFields()`: "label (xpath)"; "xpath — not in the current form; username is used when the form has it" when the saved xpath is no longer a question (spec scenario "Selected question removed by a redeploy"); "username (form metadata)" when none is set and the metric is available; "None" otherwise. "Change" (admin) reveals the select + Save and moves focus to the select; auto-expanded when the metric's hint is `selectEnumeratorField`.
- **Name and time zone** (General): one form with both fields and one Save (they were two forms with two Saves); the time-zone hint shrinks to one sentence; the time-zone select groups zones by region (`<optgroup>` by the part before the slash) with UTC first and a "Use my browser's time zone" ghost button that selects `Intl.DateTimeFormat().resolvedOptions().timeZone`. Non-admins see a read-only "Time zone" row in the Kobo form list.
- **API token** (General): "Replace API token" becomes a ghost button after Re-check with `aria-expanded`/`aria-controls`; the revealed form gains Cancel and focus moves into the token input.
- **Indicator metadata** (Scripts): a one-line summary "label · name · format · unit" with "Edit details" (analyst+, not while viewing an older version) that expands `IndicatorMetadataFields` in place; auto-expanded while `fieldErrors()` is non-empty or the metadata is dirty, until saved or reset. Viewers and older versions get a `<dl>`, not disabled inputs.
- **Sampling frame**: read-first (D12).

Rare creation flows open in dialogs built like `ReferenceUploadDialog`: **Add member** (email, role, hint, field errors, general alert, `novalidate`; closes on success, toast, reload) and **Import sampling frame** (file → preview summary → row errors or mapping selects → "Load into the editor"). Replace of a reference table reuses the upload dialog prefilled with the name read-only, so its errors stay inline instead of a toast.

### D7. Dashboards

- **Performance.** Opens with a headline strip of the three figures the spec names, Submissions, Median completion time, Overall coverage (`grid-cols-3` from `sm`, stacked labels at 360 px; "—" plus a two-word reason when a part is unavailable or no frame exists), followed by the detail cards; the three tiles leave their cards so nothing is shown twice. The range and freshness toolbar is one plain row: the two native date inputs always visible inside a `<fieldset>` with an sr-only legend "Date range", Clear and Refresh as secondary `sm` buttons, and one muted status line "Computed at … · Days are counted in UTC. · Set the project time zone" (link admin-only). No overlay for the range: the spec's field-error scenario needs the inputs in the page. Completion keeps the mean and a secondary counts line ("1 outlier (under 5.0 min or over 50.0 min) · 4 unusable durations"); when nothing is usable it shows that line and the unusable count only. The without-time count becomes a footnote under the per-day block with the digit in `data-testid="without-time"`. "Submissions per day" and "Completion time" share a row from `lg`. The outside-the-frame list moves below the targets table as a compact table reusing the dimension headers plus a "Submissions" column. Unavailable-metric alerts stay full alerts with their link only for roles that can act (analyst+ for completion, admin for the enumerator question); other roles get one muted line that still names the missing fields or whom to ask. Phone cards for enumerators and coverage become two lines that keep codes with labels. The loading skeleton matches the final layout.
- **Clean data.** The toolbar card becomes a plain row (source switch, table select); one muted meta line "Published … by run … · Times in {zone}" with the `published` and `zone` test ids as spans; a results line rendered whenever a table is selected holds the row count on the left and the Export trigger on the right (outside the `page()` block so Export keeps working after a page error); column headers put label and type on one secondary line; the paging nav hides when rows are empty or total ≤ 25; the no-rows message is a plain line without a second "Clear filters" button; the "is one of" help shows only when the list may be incomplete; the analyst empty state is heading, one sentence, button.
- **Indicators.** Canvas first; the inventory as a `tmz-disclosure` "Indicators (N) · M published" after the grid (collapsed once any has published) and merged, expanded, into the empty state while none has; the toolbar card becomes a flex row above the grid shown to editors (count merged with the limit message) and hidden when there are no widgets, with "Add widget" inside the "No widgets yet" card; inventory rows are one wrapping line (label, muted `code` name, format · unit, status badge, "Published {date}" for published rows, row count, a `sm` ghost download icon button `aria-label="Export {label}"` only for published rows); the per-widget "Show as table" toggle moves into the tile header as a `size-9` icon button with `aria-pressed`, shown only when `WidgetView` reports a drawable result (`tableAvailable` output, `asTable` input, `WidgetGrid` owns the per-widget state); editor tile actions collapse to the move handle plus one `tmz-dropdown-menu` (Edit, Remove as `danger`); not-published tiles render at a compact height until their indicator publishes; the row-limit notice is a one-line muted text; the pie legend sits beside the pie when the tile is wider than tall; the widget dialog folds Filters into a disclosure "Filters (n)" (open when filters exist), merges the format note into the indicator hint, hides the plot-mode select when the table has fewer than two numeric columns, sizes the preview by chart type, and from `lg` shows fields and a sticky preview side by side in a wider dialog.

### D8. Date and time format

One constant `dateTimeFormat = 'MMM d, y, h:mm a'` exported from `shared/ui` and used by every `date:` pipe that today uses `'medium'`; dates without a time keep `'mediumDate'`. Tests that pin a formatted string change their expectation. Rationale: ten-plus values per page with seconds were the single largest source of visual noise on Submissions and widened the enumerator and log tables into horizontal scroll.

### D9. Busy state and announcements

Long actions (export in both dashboards, download link, test start) show their busy state on the pressed control (`aria-busy`, label "Preparing…" or a spinner with visually hidden text) and end with one toast, success or failure; the "Preparing the export…" info toast is dropped. Exporting is tracked by item (indicator name, table name) so other controls of the same kind stay usable; the API's 429 stays the one-at-a-time authority. `Alert` gets `role="status"` for non-danger tones when inserted after an action (republished, table gone, dropped filters), so screen readers hear the notice; the clean data page clears `dropped` and `republishedAt` on the next user-initiated navigation (`go()` with `replace === false`), not in `received()`, because `recover()` sets them right before a replace navigation.

Order inside the editor column: picker row → indicator summary (D6) → editor → checks → action row → test panel → sample download strip; side column: side panel with tabs Tables, Reference, Versions. Runs: a one-line last-run strip under the picker (status badge, relative time, failed step when failed, "Run now" for analyst+, a link to `#runs`) and the full runs list at the bottom with `id="runs"`; `runEnded → reloadInputs` keeps working from the strip. Details:

- **Picker row**: `[1. Clean] [2. Output] [Indicators (n) ▾]`; the third control is a CDK menu built like `template-menu.ts` (two-line items: label and `code` name, version badge), with a filter input at the top when n > 10, and shows the selected indicator's label (or the new indicator with its "new" badge) when one is selected. "Add indicator" stays a separate button (analyst+); the limit message renders as text under the row only when it applies. Version badges show only on the selected kind. The "Indicators 0 / no indicators yet" text lives inside the menu, not above the editor of another script.
- **Action row**: Save (primary), Test on sample and Download sample (secondary) with the sample-size field inline (the local-dev-kit spec requires Download sample next to Test on sample with the same field), Templates as its own menu, an overflow menu for Upload .py and Remove script. The two hint paragraphs become one short hint under the sample-size field; the three-line download explanation moves into the download strip's first state.
- **Text around the editor**: the contract paragraph goes (the Reference tab has the contract; the signature appears as a `code` chip in the editor label); `scripts.editor.keys` splits into the always-shown "Tab indents. Press Esc, then Tab, to leave the editor." and the Ctrl+Enter sentence shown only while `canEdit() && !viewing()`; the problems list is titled "Checks (n)" for every role, and the "never blocked" hint shows only to editors.
- **Test panel**: rendered as the next sibling after the action row (DOM order keeps the side panel after the editor, as a test asserts); `scrollIntoView({ block: 'nearest' })` when the panel first appears and the test was started with the button, never for Ctrl+Enter; no focus move; the success sentence that repeats the badge is dropped.

- **Runs list**: step badges only when a step failed or was skipped; the "Script versions" column leaves the table and the run details dialog shows "Script 1 v4 · Script 2 v2" in its header next to the trigger.
- "When scripts run" leaves this page (D6).

### D11. Submissions page

Order: status block (card: the `<dl>` with the stored count as the only `text-2xl` figure, the deleted count at normal size, `sm:grid-cols-3`, the active-sync `role="status"` line, Sync now / Full resync for analyst+), then the schedules line with the admin Edit disclosure (D6), then the synchronization log, then the form versions (`id="form-versions"`). The versions block loses its intro paragraph (the sentence moves into the empty state and the retry hint), gains an inline "Re-check the form" button for analyst+ that calls `ProjectsService.recheck`, updates `ProjectContext` and reloads the versions, and branches the retry hint by role (viewers are told to ask an analyst or admin, no link). The shortened version id gets a visible copy icon. The card heading `data.statusTitle` becomes "Status" since the section is now named Submissions.

### D12. Sampling frame

Read-first when a frame exists: a section `h2`, a summary line "N dimensions · M combinations · saved {date}", the read-only table paginated with the existing `pageSize`/`pageRows` logic for every role, and for analyst+ two header actions, "Edit" and "Import from file" (dialog, D6). No frame: editors land in the editor with Import prominent; viewers see the empty card. Editor: one "Dimensions and targets" block (general alerts on top; dimension rows with visible "Name" and "Form field" labels, "Add dimension" directly under the list; the grid only when there are dimensions, with "Add row" and a pager aligned to the Performance markup below it; the empty hint inline). Field selects suffix questions in a repeat group or multiple-choice ("— in a repeat group", "— multiple choice"), never disable them (the dashboard spec counts them with a warning), and show the matching coverage warning text under the select while such a field is selected. Save stays at the bottom (no sticky bar, it fights the phone keyboard); on a failed save the page jumps to the page holding the first failing row and the counter names it; `setFrame` no longer resets the page after a successful save; Cancel reverts to the saved frame; a `dirty` computed feeds a `canDeactivate` on the route reusing the Scripts guard shape. The import error alert says "and N more" beyond the first 20 rows.

### D13. Members, Reference data, Webhook

- **Members**: list first as one `<ul>` at every width (name, email when present, role badge, kebab), horizontal rows from `sm`; heading row with "Add member" (admin) opening the dialog (D6); pending invitations folded into the list as rows (email, "Invited as {role}" badge, kebab with Revoke as `danger`); "You" badge on the current user's row (`CurrentUserService.user()?.id === member.userId`, nothing while null); when the list holds exactly one admin, that row's menu omits demotion and removal (the API's last-admin rule made visible; the 409 handling stays); self-removal uses a second-person confirm message; a loading skeleton.
- **Reference data**: intro paragraph removed (the upload dialog keeps its hints); empty state as a plain block with the role's sentence and, for editors, the Upload button; Preview stays the one visible row action, Replace and Delete move into a `tmz-dropdown-menu` with `aria-label="Actions for {name}"` (canEdit only); phone cards show name plus one meta line; counts use the number pipe; one presentation of "updated" in both layouts; the preview dialog passes the original header as the column label only when it differs from the name and gets a `fill` input on `TablePreview` so the dialog body is the single scroll region; the post-upload rename notice becomes one dismissible line with a disclosure listing the renames, skipped on a Replace whose renames equal the current mapping.
- **Webhook**: one card; status line first ("Last delivery received: {time}" or a warning "No delivery received yet." with a link to Submissions, one-row skeleton while pending); intro cut to one sentence; credential rows compact (label above the value, from `sm` the value and an icon-only Copy on one row; the username loses Copy; the secret row keeps Show/Hide, Copy and a demoted secondary `sm` "Regenerate secret"); the setup steps in a disclosure open while no delivery has arrived; in the secret-unreadable state the mask, Show and Copy are not rendered and the alert carries the Regenerate action; the masked value gets visually hidden "Hidden" text; one noun "secret" in the UI with "password" mentioned once in the steps; `!context.can('admin')` renders an admins-only alert instead of calling the API, and a failed request shows a danger alert instead of a skeleton.

### D14. Tests

`project-page.spec.ts`: the expected top-level list is `['Performance', 'Clean data', 'Indicators', 'Settings']` for every role; new cases for Settings `aria-current="true"` on `/members`, the pill row's contents by role, the `<optgroup>` in the select, no pill row on dashboards, and focus on in-app pill navigation; the `tabs()` helper and the dashboard specs that read `nav a` scope to the first `nav`. `openProjectSection(section, role)` is unchanged because routes are unchanged. Dialog-based flows (add member, import frame, replace reference) test through the overlay container like `project-reference.spec.ts`. Disclosure-based content is asserted after opening the `<details>`. Formatted dates and the reworded strings update their expectations. The two pre-existing polling failures on this machine are not regressions.

## Risks / Trade-offs

- [Analysts reach Scripts in two clicks instead of one] → the dashboards' empty states and "See the runs" link straight to Scripts; a role-conditional fourth tab is a one-line follow-up if it hurts.
- [The "Settings" label covers a sync log, an editor and a run log] → the secondary row names each section; "Setup" and "Configure" were judged less conventional.
- [Tests that read `nav a` see the pill row when a configuration section is open] → scope those assertions to the first `nav`; the dashboard specs only read the first three links.
- [Default-open disclosures shifting content after load] → evaluate the rule once when data first arrives, never on polling refreshes (D5).
- [Fragment targets that render after data loads] → General handles `enumeratorField` itself (D3); the other targets (`runs`, `form-versions`) are static headings.
- [Native `<details>` styling differs across browsers] → the shared component hides the marker and draws its own chevron and focus ring; checked in Chrome and Firefox during verification.
- [Moving "When scripts run" changes where analysts see the run schedule] → the Scripts page keeps a read-only summary line linking to the edit location; the runs list still shows each run's trigger.
- [The `date:` format change touches many templates and expectations] → one constant, one mechanical pass per section inside that section's task group, so failures stay local.
- [Large diff across twelve pages] → the task groups are independent after groups 1 and 2; each can be implemented, tested and reviewed on its own, and later groups can be deferred without breaking earlier ones.
- [Export busy state per item relies on the API refusing concurrent exports] → the 429 `exportBusy` path already exists and is tested; the UI only stops disabling unrelated controls.

## Migration Plan

No API, database or deployment change. The UI ships as one image; no URL changes, so no redirects and no documentation links break. Rolling back is redeploying the previous image. Docs are updated in the same change so wording matches the screen (task group 13).

## Open Questions

None that change the specs, the approach or the task breakdown. Two product preferences can be decided during implementation without affecting them: whether the Settings tab keeps the gear icon beside its label or shows the label alone, and whether the phone select's Settings group label reads "Settings" or "Project settings".

## Verification Results

### Unit and component suite (task 13.2)

### Stack verification (task 13.3)

Run in a separate Compose project (`tamizaverify`, port 8189, own env file, a fake OpenID Connect provider and a fake Kobo on the host), with the user's own stack untouched. The project had a form with a repeat group, a multiple-choice question and 84 submissions, two indicator scripts run once, two dashboard widgets, a sampling frame, and three users (admin, analyst, viewer). Headless Chrome drove it over the DevTools protocol at 360, 1024 and 1280 px. The final run passed all 154 checks (admin at all three widths, analyst and viewer at 360 and 1280).

Checked and passing:

- **Navigation.** Four top-level tabs on wide screens. One select with a Settings group below `md`, listing Webhook for admins only. A pill row on each configuration section with the right sections per role and exactly one current pill. No pill row on the dashboards. The admins-only message on Webhook for analysts and viewers.

Submissions schedules line, with the form shown only after Edit. Scripts picker row, last-run strip, indicator menu and Tables, Reference and Versions side tabs. Members list and the Add member dialog. Sampling frame read view, Import dialog with mapped dimensions, imported rows opening the editor with nothing saved, and the marks and warning on repeat-group and multiple-choice questions. Webhook no-delivery line with its link, steps open, and no Copy on the username.

Defects the real stack found, fixed and covered by new unit tests:

1. **Import mapping not preselected.** In the import dialog the pre-selected form field used the loop index of the field list instead of the dimension's own index, so a dimension matched only when the two positions coincided. The same slip was in the code this dialog replaced. It now uses the dimension's index.
2. **Multiple-choice questions not recognised.** The API stores an XLSForm-style row such as `select_multiple services` with the type `select_multiple_services`, and the dashboard matches by prefix. The editor compared the whole type, so those questions got no mark and no warning. It now matches by prefix too.
3. **Horizontal scroll on Scripts at 1024 px.** The three side-panel tabs overflowed their column by 10 px. The tab row now wraps.

Observations left as they are:

- At 360 px the Scripts actions menu (the three dots) sits alone on the line after Templates. It is reachable and does not scroll the page, but a tighter grouping is possible.
- On Webhook the username box is a little narrower than the URL box, because the username row has no Copy button. Cosmetic.
- On the Performance page the sample data produced "Outliers are surveys shorter than 0 min" because every duration is close to the others. That is the existing outlier rule on uniform data, not a layout problem.
