# UI deviations and findings

Where the UI half of `improve-map-widget` read the design differently from its letter, or found a Leaflet 1.9.4 or builder behaviour the design did not foresee. Each entry says what was done instead and why.

## Verification mechanics

- **Spec files cannot read files with `node:fs`** (tasks 1.3 and 7.1). The unit-test builder bundles for the browser, so `node:fs` and `node:path` do not resolve. Instead, `angular.json` maps the `.css` extension to the `text` loader (like `.py`, which the script templates already use), with `src/css-modules.d.ts` declaring `*.css`, and the specs import `src/styles.css` and `leaflet/dist/leaflet.css` as strings. The 7.1 spec does the same with the nginx files (`.conf`). The production build is unaffected: global styles do not go through that loader, and `npm run build` output is the same.
- **The guard of task 1.8 is a shell script**, `scripts/check-ui-safety.sh` (`npm run check:safety` in `tamiza-ui/`), the fallback the task names. It cannot be a spec because a spec cannot list `src/app/**/*.ts` (no file system, and the bundler cannot import every `.ts` as text). It was verified on a planted `innerHTML` line: it fails with exit 1 and passes again once the line is removed.
- **Map positions in specs** (task 1.5: "north up", "fits", "lone point"). The Leaflet map is not reachable from a spec, so they are read from the SVG paths (their coordinates are the container's pixels while the view is the fitted one) and from the `data-zoom` and `data-center` attributes of the map container, instead of `latLngToContainerPoint`. The attributes are set from the widget's `current` view signal.
- **jsdom has no 3D transforms**, so Leaflet's `any3d` is false there: `zoomSnap` is read as 1 (whole-number fits) and zoom is not animated. The specs therefore check `zoom ≤ -7` for a 100 km planar map rather than a fractional fit. Real browsers use the 0.25 snap of design D3.

- **Tab in jsdom.** jsdom does not move focus on a Tab key. "One Tab stop" (task 2.3) is therefore checked structurally: after Enter, an arrow and Escape, no shape has a `tabindex` other than the `-1` it carries while it is the keyboard's (none after Escape), the focus is on the map container, and the first tabbable elements of the widget, in document order, are the container and then the zoom-in button. The real Tab order is part of the manual check in group 8.
- **Docker was not available for `nginx -t`.** Docker Desktop stopped (the C: drive was full at the time) before the new nginx location could be run through `nginx -t` in the nginx image. The new location copies the settings of the export-link location, and the spec pins what it must contain; the stack check of task 8.2 runs the real container.

- **Test ids of the map changed.** The map no longer has the `chart-svg` element (Leaflet owns its SVG, and the container is `role="application"`, task 2.3). Specs find the map by `map-container`, its regions and markers by `map-region` and `map-point` (set on Leaflet's paths by the engine), and its tiles by `map-tile`. Other chart types keep `chart-svg`.
- **Specs that draw a map need `stubMap()`** (`src/testing/leaflet.ts`): jsdom has no layout, no `ResizeObserver`/`IntersectionObserver`, no `matchMedia` and never loads the stylesheet `<link>`. The first spec to call `loadLeaflet()` unstubbed would leave the stylesheet wait pending for the rest of its file, so `stubMap()` also answers any stylesheet link already waiting.

## Findings in Leaflet 1.9.4

- **`redraw()` does not change the depth of a tile layer (design D15, D16).** The design says a new imagery depth updates the layer's `maxNativeZoom` and calls `redraw()`. In 1.9.4 `GridLayer.redraw()` clears the tiles and rebuilds them for the new tile zoom but keeps the tile grid (`_globalTileRange` and the wrap ranges) of the old one; they are recomputed only with the view (`_setView` through `_resetGrid`). Going from `maxNativeZoom` 15 to 20 at zoom 20 therefore drew no tile at all, because every x/y of zoom 20 was outside the range of zoom 15. `MapEngine.updateTiles` takes the layer off the map and puts it back instead (which resets the grid), and only for a change of depth. A change of link keeps using `setUrl` (without a redraw for a refresh, with one for the retry of D17), which does not change the tile zoom. `map-engine.spec.ts` ("tiles") pins both.
- **`bubblingMouseEvents` must be false on the shapes.** By default a click on a path also reaches the map's own `click`, so "tap elsewhere closes the pinned tooltip" would have closed it at the very tap that pinned it. The shapes are created with `bubblingMouseEvents: false`; a click on a shape reaches only the shape.
- **Keyboard pans are animated whatever the reduced-motion option.** `panBy` from Leaflet's arrow keys animates unless called with `animate: false`, and Leaflet has no map-wide option for it; the three options of design D5 (`zoomAnimation`, `fadeAnimation`, `inertia`, plus `markerZoomAnimation`) are set, and the widget's own pans (the reveal of a shape) pass `animate: false` under reduced motion.

## Readings

- **A tooltip pinned from the keyboard closes when focus leaves the shapes.** Design D6 lists "focus leaving the map" among the ways a pinned tooltip closes. A tooltip pinned by a tap or click stays while the member uses the map's buttons (focus moving from the map to a control inside the widget), and closes when focus leaves the widget. One pinned by the keyboard has the shape's focus as its subject, so it closes as soon as the shape is no longer the focused element, which includes moving to a zoom button.
- **The `unavailable` and `loadFailed` notices are a line below the map,** like the existing "rows left out" line, not an overlay. A map one row high has no room to hide a note over, and the line is read in order by a screen reader. The live region announces "Basemap unavailable" once when the basemap is given up.

- **The "coordinates are not degrees" note** is shown only when the member's effective basemap is one the deployment offers. A saved kind that is not offered draws nothing and raises nothing (design D11), so telling the member the basemap "cannot be shown" for another reason would be noise.
