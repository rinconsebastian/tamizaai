# Proposal

## Why

An analyst who must describe a situation, such as access to water by municipality or school attendance among displaced households, goes through the same chain every time: read the Kobo form and what the submissions hold, decide the indicators, write and test a cleaning script and one script per indicator, run the chain, then build a dashboard with the right widgets. Tamiza holds everything a model needs to do that chain with the analyst: the form with its questions and choice lists, the flattened and clean tables, the script contract and templates, the test queue, the runs, and the dashboards with their widget queries. The in-editor assistant (`add-script-assistant`) helps with one script at a time, has no tools and never sees a value of the data, so it cannot look at the submissions, test what it wrote, run the chain or build a dashboard.

The Model Context Protocol (MCP) is how Claude (claude.ai, Claude Desktop and mobile, and Claude Code) and other AI clients reach an outside system: the system publishes tools, and the client calls them on behalf of the signed-in person. With an MCP server in Tamiza, the analyst can ask in a Claude conversation, "describe the access to water by municipality with the last survey", and Claude can read the form and summaries of the data, propose the indicators, write and test the scripts, run the chain, create the dashboard and its widgets, and read back what they show, acting with the analyst's own account and role.

## What Changes

- **An MCP server in the `api`**, at `<TAMIZA_PUBLIC_URL>/mcp` over Streamable HTTP, off until the operator sets `TAMIZA_MCP_ENABLED=true`. It makes no outbound request and calls no model: the AI client brings the model, and the person's Claude plan pays for it.
- **Sign-in with Keycloak.** The client signs the person in through Keycloak with OAuth (authorization code and PKCE) using a public client that the operator registers once (`tamiza-mcp`, with Claude's callback addresses). Its tokens carry an audience of their own: the `/mcp` endpoint accepts only that audience and `/api/v1` keeps refusing it, so a token held by an AI client can only do what the tools allow. Tamiza publishes the protected resource metadata that clients use to find Keycloak. Every call acts as the signed-in person, with their role in each project, exactly as the UI does.
- **Two locks on the data.** The operator sets the most a deployment allows (`TAMIZA_MCP_MAX_DATA_ACCESS`, `aggregates` by default, or `rows`), and the admin of each project chooses, in **Settings > General**, *Off* (the default for every project, new and existing), *Summaries only* or *Summaries and rows*. With summaries only, the client sees the form, the tables and columns with their types and question labels, row counts, column profiles (empty values, distinct values, ranges and quantiles of numbers and dates, counts of each choice label, and the values of short lists that 5 or more rows share), the scripts, run and test results reduced to their shape with masked errors (as the assistant sends them), and what the indicator tables and widgets show. Rows of the raw, clean, output, indicator and reference tables, test previews, `ctx.show` values and unmasked logs need *Summaries and rows*.
- **About thirty tools**, each with the role its REST endpoint requires: orientation (`list_projects`, `get_project`); the Kobo data (`get_form`, `get_tables`, `profile_table`, `get_fieldwork`, and `query_rows` with rows allowed); the scripts (`get_authoring_guide`, `list_scripts`, `get_script`, `list_script_versions`, `save_script`, `remove_script`, `restore_script_version`); tests and runs (`test_script`, `get_test`, `start_run`, `get_run`, waiting up to two minutes inside one call); indicators (`list_indicators`, `get_indicator_columns`, `query_indicator`); and dashboards and widgets (`list_dashboards`, `get_dashboard`, `get_widget_data`, `create_dashboard`, `update_dashboard`, `duplicate_dashboard`, `remove_dashboard`, `create_widget`, `update_widget`, `remove_widget`). Each tool runs the same validation and code as its REST endpoint. Removing a dashboard or a widget cannot be undone, so those tools must also be given its name or title. The tools that save, remove or restore a script must be given the current version number, so a script another member changed in the meantime is never overwritten by mistake. Scripts run without a strong sandbox, and text in a form or in the data could mislead a client, so code that an AI client sends is refused when it imports modules scripts never need (`os`, `subprocess`, `socket`, …), calls `eval`, `exec` or `open`, or holds a web address. The editor keeps accepting such code from a person, as today. A `describe_situation` prompt and the server's instructions walk the client through the chain.
- **Records and limits.** Each call is recorded (who, project, tool, data access level, outcome, duration, result size; no arguments and no results), kept 180 days, and the 50 most recent calls of a project are listed under the switch in **Settings > General**. Script versions saved through MCP are marked "via MCP" in the Versions tab. A person may run at most 4 calls at once and 120 calls a minute, and a result longer than 60,000 characters is cut and says how to ask for less.
- **Connect page.** When the server is enabled, the top bar offers **Connect an AI client**: the MCP address, the client ID, and the steps for claude.ai (custom connector), Claude Desktop and Claude Code (`claude mcp add` with `--client-id` and `--callback-port`), and how to revoke a connection.
- **Deployment.** `nginx.conf` proxies `/mcp` (with a 300-second read timeout and no buffering) and `/.well-known/oauth-protected-resource`. `compose.yaml` and `.env.example` gain the `TAMIZA_MCP_*` variables. For claude.ai, Claude Desktop and mobile, the Tamiza address and Keycloak must be reachable from Anthropic's servers; Claude Code connects from the analyst's own computer.
- **Docs.** A new `docs/mcp.md` (connecting, what a client can see at each level, the tools, a worked "describe a situation" session, revoking), a "Client for AI clients (MCP)" section in `docs/keycloak.md`, an "MCP server" section in `docs/operations.md`, and updates to `README.md`, `docs/tamiza-brief.md` and `openspec/config.yaml`.

No breaking changes: with `TAMIZA_MCP_ENABLED` unset nothing changes, and once it is set, every project stays off until its admin turns it on.

## Capabilities

### New Capabilities
- `mcp-server`: the MCP endpoint of the `api`: when it exists, how clients sign in and which tokens it accepts, the data access levels and who sets them, the tools with their roles and what each returns at each level, waiting for tests and runs, guards on changes, result size, limits and records, the connect page, and the activity list of a project.

### Modified Capabilities
- `projects`: a project admin sets the project's access for AI clients (off, summaries only, or summaries and rows, up to the deployment's maximum), and the project details include it for admins and analysts.
- `script-editor`: the Versions tab marks the versions saved through MCP.
- `deployment`: besides `/api/`, the `ui` exposes `/mcp` and `/.well-known/oauth-protected-resource` from the `api` when the MCP server is enabled.

## Impact

- **tamiza-api**: an `Mcp` area on the official C# SDK (`ModelContextProtocol.AspNetCore`, pinned): options bound to `TAMIZA_MCP_*` and `Mcp__*`; a second JWT bearer scheme for the MCP audience, chosen by path, with the SDK's challenge and protected resource metadata; the tools, the prompt and the server instructions; an access check per call (role, project level, deployment maximum); a ledger with rate limits; a `ColumnProfiler` in SQL on the published tables, cached per publish; the endpoint handlers the tools reuse become `internal`, and the assistant's `TestFacts` and `Masker` are reused for summaries; `GET /api/v1/mcp` (connection details) and `GET /api/v1/projects/{projectId}/mcp-calls` (activity); `mcp: { enabled }` in `GET /api/v1/system/config`; `mcpAccess` in the project update and details; a DbUp migration adding `projects.mcp_access`, `script_versions.origin` and `tamiza.mcp_calls`.
- **tamiza-ui**: the "AI clients (MCP)" card with the activity list in Settings > General, the Connect an AI client dialog from the top bar and the menu drawer, the "via MCP" marker in the Versions tab, translations; `nginx.conf` gains two locations.
- **tamiza-analytics**: no change.
- **Keycloak**: the operator adds one public client with an audience mapper (documented, with `kcadm.sh` commands); nothing changes for the `tamiza-ui` client.
- **Deployment**: `compose.yaml`, `.env.example`. Inbound requests to `/mcp` come from Anthropic's published range `160.79.104.0/21` for the hosted Claude apps, and from analysts' computers for Claude Code.
- **Docs and planning**: `docs/mcp.md` (new), `docs/keycloak.md`, `docs/operations.md`, `README.md`, `docs/tamiza-brief.md` (sections 2.2, 6 and 8), `openspec/config.yaml` (section 2.2).
- **Out of scope, for later changes**: an MCP App (an interactive widget preview inside the conversation); a text widget so a client can write its findings into a dashboard; personal access tokens and Dynamic Client Registration or Client ID Metadata Documents as supported setups; changing settings, members, the sampling frame, the Kobo connection or the pipeline schedule; uploading reference tables; starting a synchronization; scheduled email reports and printing; MCP resources, sampling and elicitation; an MCP client inside Tamiza.
